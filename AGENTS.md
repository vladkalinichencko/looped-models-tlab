# AGENTS.md

Тестовое задание T-LAB, направление **Looped Models**.
Постановка целиком — в [NOTES.md](NOTES.md). Прочитай её перед любой работой.

## Раскладка

| путь | что там | в git |
|---|---|---|
| `NOTES.md` | задание, сетап, лог, идеи, результаты | да |
| `model.py` | Qwen3-подобный блок + `LoopedLM` с `n_loops` | да |
| `data.py` | FineWeb -> паки токенов, детерминированный train/val сплит | да |
| `train.py` | претрен под фиксированным бюджетом токенов | да |
| `eval.py` | val ppl чекпойнта, свип по числу лупов | да |
| `report.md` | финальный отчёт | да |
| `datasets/` | кэш HF-датасета | нет |
| `runs/<tag>/` | `ckpt.pt`, `history.json`, `eval.json`, графики | нет |
| `tmp/` | всё, что нагенерил агент | нет |

## Правила

- Один прогон = один `--tag` = одна папка в `runs/`. Чекпойнт сохраняется по
  лучшему val — **проверяй, что он реально сохранился**, это классический промах.
- Токенизатор один и тот же во всех сравнениях. Меняешь токенизатор — все прошлые
  ppl несравнимы, перезапускай всё.
- Бюджет токенов у всех вариантов одинаковый. Сравнение «лупы vs не лупы» при разном
  числе увиденных токенов ничего не значит.
- Модификации схемы лупинга — в `model.py`, рядом с `LoopedLM.forward`. Не плоди
  копии модели: добавляй флаг в `Config`.
- **Граница кода.** Корень — код человека: `model.py`, `data.py`, `train.py`, `eval.py`.
  `tmp/` — территория агента: варианты схем лупинга, одноразовые скрипты, логи, разборы.
  Там можно что угодно, но по-человечески читаемо.
- Из `tmp/` в корень переезжает только то, что доказало пользу, — причёсанным и со
  строкой в NOTES → «Лог».
- Каждый прогон — строка в NOTES → «Лог»: тег, конфиг, val ppl.

## Команды

```bash
source .venv/bin/activate
python train.py --tag smoke --tokens 200000 --eval-every 50   # проверить, что живо
python train.py --tag loop4 --n-loops 4 --tokens 100000000
python eval.py runs/loop4/ckpt.pt --loops 1 2 4 8 16 32
```

## История и передача состояния

Следующая сессия начинается с чистого листа и видит только репозиторий. Всё, что не
записано, потеряно.

- **Каждое законченное изменение — отдельный коммит, сразу.** Не копи правки пачкой.
- Сообщение коммита — по-русски, в повелительном наклонении, про **почему**, а не
  только что: «Починить выбор демо под формат v3.0» вместо «фикс». Если решение
  неочевидное — второй абзац с обоснованием и тем, что отвергли.
- **Состояние проекта живёт в `NOTES.md`.** После каждого прогона — строка в «Лог»:
  дата, команда, число, вывод. После каждого решения — почему так, а не иначе.
  Отрицательный результат записывается наравне с положительным.
- Нерешённое — в «Открытые вопросы», чтобы следующий не переоткрывал их заново.
- **Начало сессии:** `git log --oneline -15` плюс «Лог» и «Открытые вопросы» в NOTES.
  Этого должно хватить, чтобы понять, где всё стоит, без чтения переписок.
