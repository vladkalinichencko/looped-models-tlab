# Looped Models — много лупов без сатурации

## Задание

### О чём это

Мы занимаемся **looped-трансформерами**, где один и тот же блок из нескольких слоёв
применяется несколько раз. Такая архитектура позволяет не только делать больше
флопсов при меньшем количестве параметров, но и потенциально даёт inductive bias
к ризонингу внутри модели: она вынуждена меньше запоминать и больше вычислять, а
рекуррентная структура позволяет нативно реализовать итеративные алгоритмы.

Текущие методы сфокусированы на небольшом количестве лупов (например, 4 в Ouro или
2 в Loop the Loopies), и если лупить больше, приросты сатурируются (например, после
10 в Huginn). Также возрождается направление **DEQ**, в котором бэкпроп производится
через неподвижную точку, и следовательно приветствуется быстрая сходимость — а после
неё все вычисления становятся бессмысленными.

Мы видим в этом существенное ограничение на скейлинг флопсов на параметр, и, кажется,
можно придумать что-то лучше.

### Задача

Придумать метод, который позволит делать **много лупов**, чтобы из модели
фиксированного размера выжать как можно больше полезных вычислений.

Сделать претрен looped-трансформера на предсказание следующего токена на
[FineWeb](https://huggingface.co/datasets/HuggingFaceFW/fineweb):

| ограничение | значение |
|---|---|
| Параметры | $\le 10$M |
| Бюджет токенов | $\le 100$M |
| База архитектуры | Qwen3 (`modeling_qwen3.py`), с необходимыми модификациями |
| Количество лупов | чем больше, тем лучше |

Можно реализовать ранний выход из лупов (например, как Q-exit,
[arXiv:2204.03276](https://arxiv.org/abs/2204.03276)).

Задача — получить **как можно более низкую перплексию на валидации за счёт большого
количества лупов**. Добиться этого можно за счёт разных схем лупинга, других
нормализаций, exploration во время лупов и т.д. — рамки намеренно не задаются, все
design choices за вами.

### Критерии

Показать две вещи:

1. Вы умеете генерить хорошие идеи.
2. Вы умеете их реализовывать и проверять.

Вторая задача на первый взгляд проще — достаточно аккуратно сформулировать
постановку для кодинг-агента, и он всё сделает. Однако важно не теряться в коде,
который он пишет: следите за всем, что происходит в течение сессии. Современные
LLM умеют решать сложные открытые математические задачи, но при этом запросто
возьмут неправильный токенизатор или забудут сохранить чекпойнт.

Для первого критерия готового рецепта нет. Есть только совет: используйте
изначальный недостаток знаний в свою пользу — сначала подумайте, как подойти к
задаче, и набросайте идеи на своём бэкграунде; если сразу броситься читать статьи
по теме, вы окажетесь в той же лодке, что и все остальные в этой области. Также
старайтесь не использовать LLM для генерации идей — они пока не умеют это хорошо.

### Оформление решения

Код и отчёт (TeX или markdown) — в репозитории на GitHub, лучший чекпойнт — в
открытый репозиторий на Hugging Face. В коде должны быть **как минимум** скрипты
для запуска обучения и эвала обученного чекпойнта. Отчёт должен содержать подробное
описание всех экспериментов и финальной архитектуры с анализом того, почему именно
такой вид даёт лучшие результаты.

Кроме того, желательно обосновать, **почему метод будет работать хорошо и на большем
скейле**. Так, например, добавить большую обучаемую матрицу value embeddings — плохо,
потому что польза от неё быстро умрёт при скейлинге параметров и бюджета обучения.

> Примечание: отсутствие положительного результата при хорошем анализе всех
> негативных — хороший результат.

## Диагностика

Единый HTML всех artifact-rich запусков и старого screening.

- Один фиксированный clean held-out набор из selection split задаёт реальные примеры для всех сравнений. HTML показывает исходный текст, token IDs, targets, decoded prediction и top-k токены на одних позициях. Final-validation остаётся закрытым до итоговой оценки.
- Один регулятор времени совместно выбирает checkpoint, пример, token position, слой внутри recurrent block и loop step. Все состояния, logits, loss, uncertainty, Jacobian и градиенты на экране относятся к этой точке.
- Для каждого checkpoint и loop step сохраняются recurrent state \(h_t\), приращение \(\Delta h_t=h_{t+1}-h_t\), logits, token-level loss, top-1 flip, entropy softmax, top-1/top-2 margin, \(KL(p_t\|p_{t+1})\), \(JS(p_t,p_{t+1})\), \(\|\Delta z_t\|\) и \(\|J_{z,t}\Delta h_t\|\). Trace Fisher и expected gradient magnitude сохраняются вместе с точным определением пространства градиента и использованного оценивателя.
- Среднее \(\mu\), projection basis и масштаб осей обучаются один раз на объявленных clean held-out states baseline, сохраняются как артефакт и затем не меняются между checkpoints, loop steps и вариантами. Рядом с 2D-траекторией всегда показаны \(\|\Delta h_t\|\), cosine соседних шагов, loss, KL и decoded prediction в полном пространстве.
- Геометрия не сводится к одной 2D-картинке. HTML показывает полный covariance spectrum reference states, reconstruction-error curve по всем рангам, разложение \(\Delta h_t\) на компоненты вдоль и поперёк reference subspace и расстояние состояния до этого subspace. Порог, после которого состояние объявляется off-manifold, не вводится без отдельной гипотезы.
- Для update map \(F\) сохраняются локальные Jacobian diagnostics. Полный \((Td)\times(Td)\) Jacobian не материализуется: показываются матрица норм token-to-token блоков, точный \(d\times d\) блок выбранного токена, ведущие singular values и соответствующие направления через JVP/VJP, а также eigenvalues там, где проверяется динамическая устойчивость. Локальная оценка Lipschitz равна \(\sigma_{\max}(J_F)\); отдельной "матрицы Липшица" нет.
- Градиент \(\partial L/\partial h_t\) сохраняется на повторах, через которые должен идти backprop. HTML совмещает его направление с \(\Delta h_t\), principal directions reference states и чувствительными направлениями Jacobian.
- Reset, zero, freeze и пропуск отдельных повторов проверяют причинную роль состояния. Exploration сначала проверяется как causal perturbation: одинаковый по масштабу шум направляется отдельно вдоль reference subspace, поперёк него и вдоль ведущих right-singular directions Jacobian; затем измеряется, возвращается ли траектория, меняются ли logits и улучшается ли loss. Sampling глубины Huginn и entropy exit-distribution Ouro показываются отдельно, поскольку они исследуют число шагов, а не hidden-state space.
- Один diagnostic denoiser можно обучить на clean held-out baseline states, затем заморозить и применять ко всем вариантам. HTML показывает вход, восстановленное состояние, residual \(D(h_t)-h_t\) и его направление в общей системе координат. Denoiser не входит в LM forward и не добавляет loss модели до отдельного согласованного эксперимента.
- Для раннего выхода показываются exit depth каждого токена, prediction на момент выхода, fixed-depth контроль, все uncertainty signals и failure cases. Learned head сравнивается с Oracle, который знает фактическое изменение held-out loss на следующем шаге, но Oracle используется только как диагностический верхний предел.
- Каждый содержательный запуск создаёт один HTML со ссылками на checkpoint, Python-конфиг, лог и сохранённые tensors или JSON. Модель служит навигацией: recurrent block раскрывается до реальных слоёв и shapes, выбранное состояние раскрывается до значений, геометрии, logits и backward path. LR, parameter groups и shape asserts остаются проверкой проводки запуска.

## Эксперименты

Все варианты используют одну реализацию Qwen3-блока и один train/eval/diagnostic path. Сначала полностью диагностируются один clean Qwen3 baseline и один корректный Huginn baseline. Следующий метод формулируется только из их измеренной динамики.

Литературные варианты пока образуют обзор, а не очередь экспериментов:

- [Universal Transformer](https://arxiv.org/abs/1807.03819) повторяет общий transition block, добавляет сигнал номера шага и может использовать per-token Adaptive Computation Time.
- [Huginn](https://arxiv.org/abs/2502.05171) разделяет модель на prelude, recurrent core и coda; каждый повтор получает исходное \(e\) через concat adapter, состояние начинается со случайного \(s_0\), core заканчивается RMSNorm, глубина сэмплируется из lognormal-Poisson, а gradient идёт через последние повторы. Статья отдельно сообщает, что add injection работал на малом масштабе, concat лучше масштабировался, step-conditioned core хуже экстраполировал, а шум после recurrent transition не помог.
- [Ouro](https://arxiv.org/abs/2510.25741) повторяет весь общий стек без отдельной input injection, использует sandwich RMSNorm и linear per-token exit gate. Expected token loss и entropy exit-distribution обучают распределение глубины, Q-exit детерминированно выбирает его квантиль.
- [PonderNet](https://arxiv.org/abs/2107.05407), [PALBERT](https://arxiv.org/abs/2204.03276), [Adaptive Computation Time](https://arxiv.org/abs/1603.08983) и Ouro дают разные варианты головы остановки: условная вероятность остановки, prior на глубину, expected loss, deterministic Q-exit или ponder cost. Они задают варианты одного будущего эксперимента, а не отдельные обязательные запуски.
- [Механистический анализ looped-моделей](https://arxiv.org/abs/2604.11791) описывает слой, группу и полный стек одним размером циклического recurrent block. Он показывает, что отдельные слои цикла могут приближаться к разным fixed points, поэтому основной объект диагностики находится внутри цикла, а не только после полного повтора.
- [Stable Architectures for Deep Neural Networks](https://arxiv.org/abs/1705.03341) связывает устойчивость глубокой residual-сети с устойчивостью дискретизации ODE и строит обратимые, ограниченные по энергии переходы.
- [AntisymmetricRNN](https://arxiv.org/abs/1902.09689) помещает собственные значения непрерывной динамики около мнимой оси, добавляя малое затухание для устойчивых долгих траекторий.
- [Unitary Evolution RNN](https://arxiv.org/abs/1511.06464) и [dynamical isometry для gated RNN](https://arxiv.org/abs/1806.05394) сохраняют чувствительность на длинном горизонте, удерживая singular values state-to-state Jacobian около единицы.
- [Jacobian regularization для DEQ](https://arxiv.org/abs/2106.14342) управляет сходимостью через Jacobian update map. Для нашей задачи тот же объект измеряется, но цель не обязана быть быстрой сходимостью.

Три идеи проверяются отдельно на одном 16-cycle path:

1. **Active Learning для дополнительного compute.** На шаге \(t\) измеряются entropy, \(JS(p_t,p_{t+1})\), \(\|J_{z,t}\Delta h_t\|\) и Fisher length \(\Delta h_t^T F_h\Delta h_t\). Их проверяют как предикторы фактической пользы следующего цикла \(L_t-L_{t+1}\). Правило распределения циклов вводится только для сигнала, который устойчиво ранжирует эту пользу на held-out данных.
2. **Антисимметричный recurrent transition.** Повторяется \(h_{t+1}=(1-\gamma)h_t+\sigma(g([h_t,e]))(W-W^T)h_t\). Вариант \(\gamma=0\) сохраняет тангенциальный линейный update, но допускает рост нормы второго порядка. Калиброванный вариант начинает с \(\gamma=0.196\), выбранного так, чтобы среднее относительное изменение \(\|h\|^2\) на held-out траектории первого checkpoint было нулевым; затем \(\gamma\) обучается вместе с моделью.
3. **Controller и четыре специализированных блока.** GRU получает исходный embedding и историю предыдущих действий. На обучении oracle выбирает блок с минимальным token CE, recurrent state следует этому teacher-forced маршруту, а controller обучается отдельным CE к oracle action. Блоки обучаются суммой собственного token CE и contrastive repulsion между их updates; на инференсе softmax controller смешивает четыре proposals.

слои соседних циклов по relative update, state norm и probe loss. Eval depths
равны 0, 1, 2, 4, 8 и 16. Прогон проверяет проводку и визуализацию, его budget
